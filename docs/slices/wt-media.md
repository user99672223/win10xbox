# Slice: wt-media

Wine's conformance suites for propsys, windowscodecs, mlang, gdiplus and dwrite (`dlls/<dll>/tests`, Wine 11.9) built as
one PE per DLL by `wine-pe/tests/media.sh --dll <dll>` and run unit by unit through the layer, one gated ctest entry
`integration.winetest_<dll>` each (tests/winetest/CMakeLists.txt, label wine_conformance, linux-cross only, MSVC
registers nothing), baseline `wine-pe/tests/<dll>.baseline`.

* The five DLLs are in wine-pe/dlls.txt (commit 9ae3275); wine-pe run 39939220424 for the head is green.
* `resource.rc` of the gdiplus and dwrite suites (the test fonts `wine_test.ttf`, ... ship in the Wine sources) is compiled
  with windres and linked in; no `.sfd` is converted, nothing is generated by hand.
* windowscodecs: the tests reference `IID_IMILBitmap*` and the WIC metadata CLSIDs that Wine's own implib
  (`dlls/windowscodecs/uuid.c`) defines; media.sh builds a generated `windowscodecs_guids.c` that includes that file.
* dwrite is built with `-D_CRT_NON_CONFORMING_WCSTOK` (layout.c calls the two-argument wcstok, as Wine's build allows).
* No fonts are staged in the machine folder's Windows\Fonts: text/font tests are expected to fail and are recorded as such.
* Before the propsys and windowscodecs units media.sh runs `regdll.exe <dll>` (LoadLibrary + DllRegisterServer, i.e.
  regsvr32) so their COM classes would be registered as on an installed Windows. It currently returns 0x80004002
  (E_NOINTERFACE), see "Open".
* Per-unit cap: 20 s (gdiplus 40 s: `region` takes 15 s on the runner). Job time added (ci run 39939220417, linux-cross):
  propsys 6 s, windowscodecs 55 s, mlang 4 s, gdiplus 88 s (its `graphics` unit sits at the 40 s cap), dwrite 12 s;
  about 3 minutes in all.

## What still fails

* windowscodecs and propsys: every failure is REGDB_E_CLASSNOTREG (0x80040154). `regdll.exe` (media.sh's regsvr32 step)
  returns 0x80004002 (E_NOINTERFACE) because `DllRegisterServer` of both DLLs goes through winecrt0's
  `__wine_register_resources`, which needs the ATL registrar (`atl100.dll`, `AtlCreateRegistrar`) and atl100.dll is not a
  builtin (not in wine-pe/dlls.txt). Adding atl100 to wine-pe/dlls.txt and re-measuring is the follow-up slice; the
  baselines of this slice are the numbers measured without it, as listed above.
* gdiplus `image` dies with c0000090 (STATUS_FLOAT_INVALID_OPERATION) after `image.c:2133: Expected 0.000000, got
  -nan(ind)`: the guest's MXCSR exceptions look unmasked; core/ has no MXCSR handling at all (not investigated, out of slice).
* gdiplus `graphics` hangs until the 40 s cap (baseline `timeout`); brush, font and metafile crash after failed assertions.
* dwrite and the gdiplus font tests need real fonts in Windows\Fonts; none are staged by design.
